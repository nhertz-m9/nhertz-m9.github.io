【Frida】エミュレータ上で動的解析

August 25, 2026

前提条件

  • Android Emulator (Android 15.0 ("VanillaIceCream") | x86_64)
  • frida-server-17.7.3-android-x86_64
  • UnCrackable-Level1

準備

  • エミュレータの CPU アーキテクチャは以下のコマンドで確認できる。
adb shell getprop ro.product.cpu.abi # -> x86_64
  • 使用している Frida クライアントと同じバージョン、エミュレータと同じアーキテクチャの frida-server を用意する。（本記事では 17.7.3）
frida --version # -> 17.7.3
  • 解凍後、/data/local/tmp/ へ設置し、起動。
adb push frida-server-17.7.3-android-x86_64 /data/local/tmp/frida-server

adb shell
chmod 755 /data/local/tmp/frida-server
/data/local/tmp/frida-server &
  • UnCrackable-Level1.apk をエミュレータ上へドラッグ＆ドロップしてインストールしておく。

動的解析

  • 起動中のプロセスを列挙する。解析対象のプロセス名 Uncrackable1 を確認。
frida-ps -Uai
  • Frida から対象プロセスへ接続できることを確認。
frida -U -n Uncrackable1
[Android Emulator 5554::Uncrackable1 ]->
  • 本記事では、VERIFY ボタン押下時のキー検証をバイパスし、任意の入力に対して常に true を返すように動的にパッチを当ててみる。

ロード済みのクラスを列挙

  • Frida の Java API を使用する。
Java.perform(function () {
    Java.enumerateLoadedClasses({
        onMatch: function (name) {
            // exclude built-in classes
            if (name.toLowerCase().includes("uncrackable")) {
                console.log(name);
            }
        },
        onComplete: function () {
            console.log("done");
        }
    });
});

  • onComplete を指定しないとエラーを吐く。

クラスのメソッドを列挙

Java.perform(function () {
    const C = Java.use("sg.vantagepoint.uncrackable1.a");

    C.class.getDeclaredMethods().forEach(function (m) {
        console.log(m.toString());
    });
});

public static boolean sg.vantagepoint.uncrackable1.a.a(java.lang.String)
public static byte[] sg.vantagepoint.uncrackable1.a.b(java.lang.String)
  • sg.vantagepoint.uncrackable1.a.a は boolean を返しており、キー検証用のメソッドである可能性が高いので、このメソッドの呼び出しをフックしてみる。

メソッド呼び出しをフック

Java.perform(function () {
    const C = Java.use("sg.vantagepoint.uncrackable1.a");

    C.a.overload("java.lang.String").implementation = function (s) {
        console.log("[+] called");
        console.log("[+] length = " + s.length);

        const result = this.a(s);
        console.log("[+] result = " + result);

        return result;
    };
});
  • 試しにテキストボックスに SECRET-KEY と入力し、VERIFY を押してみると、出力は以下となる。
[+] called
[+] length = 10
[+] result = false
  • この結果から、この関数がテキストボックスの入力内容を受け取り、キー検証していると推定できる。

検証をバイパス

  • 先ほどと同様の方法で、メソッドの戻り値を書き換えることができる。具体的な検証の内部処理を知る必要はない。
Java.perform(function () {
    const C = Java.use("sg.vantagepoint.uncrackable1.a");

    C.a.overload("java.lang.String").implementation = function (s) {
        return true; // bypassing key verification
    };
});
  • 無事に検証処理を上書きすることに成功した。

Tips

コールスタックを表示

  • あるメソッドが誰から呼ばれたかを特定する。
Java.perform(function () {
    const C =
        Java.use("sg.vantagepoint.uncrackable1.a");

    C.a.overload("java.lang.String").implementation =
        function (s) {
            console.log("[+] called");

            const Log = Java.use("android.util.Log");
            const Exception = Java.use("java.lang.Exception");

            console.log(
                Log.getStackTraceString(Exception.$new())
            );
            return this.a(s);
        };
});
