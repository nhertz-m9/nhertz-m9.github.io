【Rust】実行バイナリ解析メモ

August 20, 2026

前提条件

  • Ghidra 10.2.3

解析: fn main() を追う

  • Symbol Tree Window から、Functions -> main をクリック。
int __cdecl main(int _Argc, char **_Argv, char **_Env)
{
  int extraout_EAX;
  
  std::rt::lang_start_internal();
  return extraout_EAX;
}

LEA ECX, [FUN_14000e030]
MOV [rsp+30], RCX
LEA RDX, [PTR_LAB_1400385c8]
LEA RCX, [rsp+30]
CALL std::rt::lang_start_internal

  • この main は Rust のランタイム用ラッパ であり、本来の fn main() ではない。実際の呼び出しは std::rt::lang_start_internal() 内で行われている。

  • FUN_14000e030 が fn main() の本体を指す関数ポインタである。ECX (RCX の下位 32 bit) に格納される。

  • PTR_LAB_1400385c8 がクロージャの vtable である。RDX へ格納される。

  • fn main() を追いたいならば、FUN_14000e030 へジャンプ。Ghidra が誤ってコード領域をデータとして認識している場合は、Right Click -> Create Function で関数として登録しなおす。

補足: fn main() はどのように実行されるのか

  • std::rt::lang_start_internal() をクリック。
void __cdecl std::rt::lang_start_internal(void)
{
  // init
  
  local_50 = in_RCX;
  local_48 = in_RDX;

  // extra lines...

  if (local_b0[0] == 0) {
    thread::Thread::new();
    sys_common::thread_info::set();

    iVar4 = (**(code **)(local_48 + 0x28))(local_50);

    local_48 = (longlong)iVar4;
    if (DAT_140057178 != 3) {
      local_39 = 1;
      local_c0 = &local_39;
      sys_common::once::queue::Once::call();
    }
    return;
  }

  // extra lines...
}

(**(code **)(local_48 + 0x28))(local_50);

  • 上で代入されている通り、local_48 には vtable が、local_50 には fn main() の関数ポインタが格納されている。

  • Rust の main は内部的には impl FnOnce() -> i32 として扱われる。概念的にはこのように。

struct Main;

impl FnOnce for Main {
    fn call_once(self) {　user_main();　}
}
  • call_once は vtable に登録されている。vtable の構造は以下のようなイメージ。
+0x00 drop: fn()
+0x08 size: usize
+0x10 align: usize
...

+0x28 call_once: fn()
  • つまり、local_48 + 0x28 で call_once を指定し、local_50 に格納された main 関数ポインタを呼んでいる。
