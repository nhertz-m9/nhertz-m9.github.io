【moe.low.arc v6.14.11】SSL Unpinning

June 14, 2026

前提条件

  • Android Sdk (apktool, zipalign, apksigner)
  • Arcaea 6.14.11 (apk/xapk)
  • Ghidra

APKの編集準備

apktool d "Arcaea.xapk"
cd "Arcaea.xapk.out/unknown"
apktool d "moe.low.arc.apk" # decompress all other split apks...

cd "./config.arm64_v8a/lib/arm64-v8a" # you can find libcocos2dcpp.so here

SSL Pinning

libcocos2dcpp.so 内で独自の SSL Pinning が実装されているため、 Project: frida-android-unpinning-ssl 等の汎用スクリプトは使用できない。

Ghidraでパッチを当てる

  • Ghidra で libcocos2dcpp.so を開き、Analyze を実行。
  • Search -> Scalar Search で 408(0x198) を検索。
  • add x0, x0 でフィルタリングし、ヒットした数個の命令へジャンプし、それぞれをデコンパイルする。(Window -> Decompile)
  • 以下のようなデコンパイル結果になっている関数を見つける。（今回は SUB_009ffee4 が該当する。）
void UndefinedFunction_009ffee4(long param_l, undefined8 param_2) {
    
    mutex4lockEv(param_l + 0x198);
    // extra 2 lines..

    return;
}
  • この関数の xref から唯一の呼び出し元関数へジャンプし、該当する BL 命令を NOP する。(Right Click -> Patch Instruction)
BL SUB_009ffee4 -> NOP
  • Search -> Scalar Search で 488(0x1e8) を検索。
  • 上と同様の手順で以下のような関数を見つける
void UndefinedFunction_017e71c0(long param_l, undefined8 param_2, /* ...args */) {

    // ...
    mutex4lockEv(param_l + 0x1e8);
    // ...

    if (lVar2 + 0x28 != param_3) {
        // ...
    }
    mutex6unlockEv(param_l + 0x1e8);
    if (*(long *)(lVar1 + 0x28) == lStack_48) {
        return;
    }

    __stack_chk_fail();
}
  • 上と同様に、該当する BL 命令を NOP する。
  • File -> Export Program で ELF を選択し、任意のディレクトリにエクスポート。

APKを再ビルドする

  • パッチを当てた libcocos2dcpp.so で、元のファイルを上書きする。
  • 署名用のキーストアを作っておく。./my.keystore
apktool b "moe.low.arc" --use-aapt2 -o "moe.low.arc.apk"
zipalign -p -f 4 "moe.low.arc.apk" "moe.low.arc-aligned.apk"
apksigner sign --ks ./my.keystore --ks-key-alias myalias "moe.low.arc-aligned.apk"
# as well as other split apk folders...

APKをインストールする

  • adb デバッグが有効であることを確認する。
adb devices
  • 分割 APK のままインストール可能。
adb install-multiple "moe.low.arc-aligned.apk" "config.xxxhdpi-aligned.apk" # ...
  • 正常に起動することを確認する。

Congratulations!
